# Phase 10 — Observability and Incident Response

> **Classes:** 57–62 | **Estimated Total Time:** ~21 hours

## Phase Description

This phase builds the operational layer that makes AI security sustainable in production. Even the best controls will be challenged, bypassed, or degraded over time — and without observability, you will not know until it is too late. Learners design purpose-built logging for AI security events, implement an immutable control ledger that records every security decision, and build runtime risk-scoring systems that compute real-time threat assessments from behavioral signals. The phase then develops incident response playbooks tailored to AI-specific failure modes — because responding to a RAG poisoning incident requires different procedures than responding to a traditional data breach. Two hands-on incident simulations give learners practical experience executing these playbooks under realistic conditions.

## Main Outcome

Learners can monitor AI systems and respond to failures — building observability stacks that detect control degradation, control ledgers that provide forensic evidence, and incident response procedures that are specific to AI failure modes.

## Classes

| Class | Title | Description |
|-------|-------|-------------|
| 57 | AI Security Logging | Designs purpose-built logging for AI security events with structured schemas and retention policies |
| 58 | Control Ledger | Implements an immutable audit trail that records every security decision, override, and policy evaluation |
| 59 | Runtime Risk Scoring | Computes real-time risk scores from behavioral signals, anomaly detection, and control metrics |
| 60 | AI Incident Response | Develops playbooks and procedures for responding to AI-specific security incidents |
| 61 | RAG Poisoning Incident | Responds to a simulated document-poisoning attack using the incident response playbook |
| 62 | Agent Tool Abuse Incident | Responds to a simulated agent tool misuse event with containment, analysis, and remediation |
